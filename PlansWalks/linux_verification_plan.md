# Linux環境における動作確認プラン (pumlv-gui)

このドキュメントは、[実装計画書](./implementation_plan_260715.md) に基づき、`pumlv-gui` が Linux 環境で正しくビルド・動作することを確認するための検証計画です。

---

## 1. 前提条件と環境確認

Linux 環境で Wails v2 アプリケーションをビルドおよび実行するために、以下のシステム依存関係が満たされている必要があります。

### 1.1 システム依存関係（パッケージ）
Linux ディストリビューションごとに必要なパッケージをインストールします。

**Ubuntu / Debian 系の場合:**
```bash
sudo apt update
sudo apt install -y build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.0-dev
# 注: 環境によっては libwebkit2gtk-4.1-dev を使用する場合もあります
```

**Fedora / RHEL 系の場合:**
```bash
sudo dnf groupinstall "Development Tools"
sudo dnf install -y gcc-c++ libgtk3-devel webkit2gtk3-devel
```

### 1.2 ツールチェーン
- **Go**: `go version` が 1.20 以上であること
- **Node.js / npm**: `node -v` が 18 以上であること
- **Wails CLI**: `wails version` でインストール済みであることを確認

Wails のシステムチェックを実行します：
```bash
wails doctor
```
> [!IMPORTANT]
> `wails doctor` の結果、`System Dependencies` や `Tooling` にエラー（Missing）がないことを確認してください。

## 2. ビルドテスト手順

### 2.1 開発モード（ホットリロード）での起動テスト
開発用のホットリロード環境が動作することを確認します。

```bash
# プロジェクトルートで実行
wails dev -appargs "./examples"
```
- **確認内容**: 
  - フロントエンドとバックエンドのコンパイルが正常に通ること。
  - `examples` ディレクトリを監視対象として自動的にウィンドウが起動すること。

### 2.2 本番バイナリのビルドテスト
配布用の単一バイナリが正常にビルドできることを確認します。

```bash
# 本番ビルドを実行
wails build
```
- **確認内容**:
  - `build/bin/pumlv-gui`（実行可能バイナリ）が正常に生成されること。
  - フロントエンドアセットが Go バイナリ内に正常に埋め込まれていること。

## 3. テストケース（機能・非機能要件の検証）

本番バイナリ（または開発用起動）を用いて、以下のテストケースを実施します。

### T1: CLI起動オプションの検証 (要件 F1)
* **手順**:
  1. ターミナルから `./build/bin/pumlv-gui ./examples` を実行する。
* **期待結果**:
  - アプリが起動し、指定した `examples` フォルダ内の `.puml` ファイルの一覧がサイドバーに表示されること。

### T2: 初回起動時の自動フォルダ選択ダイアログ (要件 F2)
* **手順**:
  1. 設定ファイルがまだ存在しない（または `~/.pumlv-gui/config.json` を一時退避させた）状態で、引数なしで `./build/bin/pumlv-gui` を起動する。
* **期待結果**:
  - 起動直後に Linux ネイティブのフォルダ選択ダイアログ（GTK またはデスクトップ環境標準のもの）が表示されること。
  - フォルダを選択すると、そのフォルダの内容が正常に読み込まれること。
  - キャンセルした場合は空の画面が表示されること。

### T3: 前回フォルダの自動ロード (要件 F3)
* **手順**:
  1. アプリを起動し、T2の手順で任意のフォルダを選択する。
  2. アプリを一度終了する。
  3. 設定ファイル `~/.pumlv-gui/config.json` が作成され、`lastFolder` に選択したパスが記載されていることを確認する。
  4. 引数なしで再度 `./build/bin/pumlv-gui` を起動する。
* **期待結果**:
  - ダイアログは表示されず、前回選択したフォルダが自動的にロードされること。

### T4: ドラッグ＆ドロップによるフォルダ切り替え (要件 F4)
* **手順**:
  1. アプリを起動した状態で、Linux のファイルマネージャー（GNOME Nautilus、KDE Dolphin など）から別のディレクトリをアプリのウィンドウ内にドラッグ＆ドロップする。
* **期待結果**:
  - 監視対象フォルダがドロップされたフォルダに切り替わり、サイドバーのファイル一覧が更新されること。
  - 設定ファイル `lastFolder` がそのパスに更新されること。

### T5: メニューバーからのフォルダ選択 (要件 F5)
* **手順**:
  1. アプリのウィンドウ上部（または OS のグローバルメニュー）にあるメニューから 「ファイル」 ＞ 「フォルダを開く」 を選択する。
  2. フォルダ選択ダイアログで別のフォルダを選択する。
* **期待結果**:
  - 監視対象フォルダが選択したフォルダに切り替わり、ファイルツリーが更新されること。

### T6: ファイル監視とライブリロード (fsnotify の Linux 動作)
* **手順**:
  1. アプリ上で適当な `.puml` ファイルを表示しておく。
  2. 外部エディタ（Vim、VS Code、Gedit など）で同じ `.puml` ファイルを開き、図形を追加・変更して保存する。
* **期待結果**:
  - 保存した瞬間にアプリの WebView 側で再レンダリングが走り、プレビューが自動更新されること。

### T7: UI インタラクション (PlantUML レンダリング)
* **手順**:
  1. サイドバーで `.puml` ファイルを選択し、右ペインにプレビューが表示されることを確認する。
  2. マウスホイールでのズームイン/ズームアウト、およびドラッグによるパン操作ができることを確認する。
* **期待結果**:
  - PlantUML (TeaVM) によるレンダリングが崩れなく表示されること。
  - ズーム・パンがスムーズに行えること。

### T8: アプリケーションのクリーンシャットダウン
* **手順**:
  1. アプリケーションウィンドウの閉じるボタン（×）、またはショートカットキー `Ctrl+Q` を使ってアプリを閉じる。
  2. ターミナルで `pgrep pumlv-gui` を実行し、プロセスが残っていないか確認する。
  3. アプリケーションがリスニングしていたソケットやファイル記述子（inotify）が正常に解放されていることを確認する。
* **期待結果**:
  - プロセスが完全に終了し、ゾンビプロセスやリソースリークが発生しないこと。

## 4. Linux 環境における考慮点と注意点

### 4.1 inotify の上限（fsnotify 関連）
Linux ではファイル監視に `inotify` が使用されます。大規模なプロジェクトフォルダを指定した場合、システムの `max_user_watches` の上限に達して監視に失敗する可能性があります。
- **検証項目**: 監視対象フォルダ内のファイル数が非常に多い場合（例: node_modules 等を含む）、エラーログがターミナルに出力されないか。
- **回避策**: `sysctl fs.inotify.max_user_watches` を確認・変更する手順を `MANUAL.md` に記載する。

### 4.2 ディスプレイサーバー (X11 vs Wayland)
Linux デスクトップ環境には X11 と Wayland の2つのディスプレイサーバーが存在します。
- **検証項目**: 特に「ドラッグ＆ドロップ (F4)」の動作において、Wayland 上でファイルドロップが正しく認識されるか。
- **動作不安定な場合の対策**: 必要に応じて、Wails アプリケーション起動時に環境変数 `GDK_BACKEND=x11` を付与して起動を試みる。
